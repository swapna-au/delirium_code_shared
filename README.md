# Delirium Risk Prediction

Predicting in-hospital delirium at admission, from routinely-collected Eastern Health
EMR data. Research led by **Swapna Gokhale** (Monash University / Eastern Health), with
data engineering by Carlton St.

This is the analysis code for the published article:

> *Development of risk prediction model for delirium using routinely collected electronic
> health records.* Archives of Gerontology and Geriatrics Plus (2026).
> https://doi.org/10.1016/j.aggp.2026.100338

Release **v1.0.0** is the analysis code as used for the article. The repository contains
**code only — no patient data** (see [Data & governance](#data--governance)).

> **New here?** Download **[`docs/guide.html`](docs/guide.html)** and open it in a browser for a
> visual walkthrough of the whole flow — how to run it, how the data moves, and how the
> delirium outcome is defined.

## Quick start

You need [Anaconda / Miniconda](https://docs.conda.io/en/latest/miniconda.html) (recommended)
**or** Python 3.10–3.13. Then:

### Option A — conda (recommended, handles everything)

```bash
conda env create -f environment.yml
conda activate delirium
python run_all.py
```

### Option B — pip

```bash
# Windows
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python run_all.py
```

```bash
# macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run_all.py
```

The pipeline needs the model input `data/cleaned.csv`, which is not included (see
[Data & governance](#data--governance)). With it in place, every figure, table, model, and
report regenerates into `outputs/` and `reports/`.
A full run takes ~40 minutes (the bootstrap is the slow part).

> **SHAP note (pip only):** the SHAP importance stage needs the `shap` package, which is
> awkward to install with pip. The conda environment includes it. With pip, either
> `pip install shap` or just skip that stage — `run_all.py` continues past it and produces
> everything else.

## Results at a glance

The published article is the authoritative record of the results.

- **Cohort:** 28,965 admission episodes; 2,334 (8.1%) developed delirium.
- **Model:** a calibrated **random forest** (primary) and an L1-penalised **logistic
  regression**, from a stable core of **6–7 predictors** — age, 4AT score, anticholinergic
  burden, number of anticholinergic medications, behaviours of concern, comorbid dementia
  (+ cognitive-impairment risk in the full-data fit).
- **Discrimination:** RF c-statistic **0.877** (10-fold cross-validation), **0.909**
  (calibrated, bootstrap out-of-sample); optimism was small (0.023).
- **Calibration:** well calibrated after Platt scaling (RF slope 0.93, Brier 0.053).
- **Clinical utility:** greater net benefit than treat-all / treat-none across the relevant
  range; at a 15% risk threshold, sensitivity 0.65 / specificity 0.93, flagging ~12% of
  admissions.
- Performance was consistent across sex subgroups.

The full write-ups are in **[`reports/`](reports/)** (`results_report.md`,
`model_specification.md`) — these are regenerated by the pipeline and versioned in git.

## Repository layout

```
data/            where the model input cleaned.csv goes (not included — see below)
pipeline/        the ordered analysis stages 00–10 + common.py (shared config)
outputs/         all generated figures/tables/models  (git-ignored — regenerated on run)

```

## Data & governance

- **No individual-level data is included in this repository.** Under the study's ethics
  approval the data cannot be shared publicly — not even the de-identified model input. See
  the published article's data availability statement.
- **`data/cleaned.csv`** (the model input) is **de-identified**: all encounter/URN ids, dates,
  and ward names are dropped in `pipeline/00_prepare_data.py`.
- **Raw extracts and the `source_file_bronze.csv` join** contain identifiers and are held by
  the study team. In the `ingest/` scripts, `SOURCE_PATH` is a placeholder
  (`path/to/raw_data`) — point it at the folder holding the raw extracts.
- `.gitignore` blocks data files (`*.csv`, `*.xlsx` and similar), so none can be committed by
  accident.
- **To run with the data:** place `cleaned.csv` in `data/` and run `python run_all.py`. Or
  place `source_file_bronze.csv` in `data/` — `run_all.py` detects it and runs stage `00`
  (de-identify + clean) first to rebuild `cleaned.csv`.

**Provenance chain:**
`raw EMR/path/pharmacy extracts → ingest/ → source_file_bronze.csv → 00_prepare_data.py → data/cleaned.csv → pipeline stages 01–10`.

## Reproducibility

The published numbers were produced with **numpy 2.2.4** and **scikit-learn 1.6.1** (pinned in
`requirements.txt`); the pipeline is deterministic (`random_state=42`). `verify_outputs.py`
diffs two output folders within tolerance if you ever need to confirm two runs agree.

## A quick note on git (for anyone new to it)

- **Get the latest code:** `git pull`
- **See what changed:** `git status`
- **Running the pipeline changes files in `outputs/` — that's expected and git ignores them.**
  You never need to commit anything under `outputs/`.
- If `git status` shows changes to `reports/*.md` after a run, that's the regenerated report;
  commit it only if you mean to update the versioned results.
- When in doubt, don't force anything — ask.
